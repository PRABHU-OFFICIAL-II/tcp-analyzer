---
  Step 1 — Install system dependencies on the VM

  sudo apt update && sudo apt upgrade -y

  # Python 3.11+
  sudo apt install -y python3.11 python3.11-venv python3.11-dev python3-pip

  # Node.js 20 (LTS)
  curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
  sudo apt install -y nodejs

  # Scapy needs libpcap + tshark
  sudo apt install -y libpcap-dev tcpdump

  # nginx (for serving the built frontend)
  sudo apt install -y nginx

  # Optional: git if you're cloning instead of copying
  sudo apt install -y git rsync

  ---
  Step 2 — Transfer the project to the VM

  Option A — rsync from your Windows machine (from PowerShell/WSL):
  rsync -av --exclude='.venv' --exclude='node_modules' --exclude='__pycache__' \
    /mnt/c/Users/ppenthoi/Documents/DEV/tcp-analyzer/ \
    user@your-vm-ip:/opt/tcp-analyzer/

  Option B — zip and scp:
  # On Windows (in WSL or Git Bash), zip excluding venv/node_modules
  zip -r tcp-analyzer.zip . -x ".venv/*" -x "node_modules/*" -x "__pycache__/*"
  scp tcp-analyzer.zip user@your-vm-ip:/opt/
  # On VM:
  cd /opt && unzip tcp-analyzer.zip -d tcp-analyzer

  ---
  Step 3 — Copy the Gemma model to the VM

  The model folder on your Windows machine is:
  C:\Users\ppenthoi\.cache\huggingface\hub\models--google--gemma-4-12b-it\

  Copy it to the VM:
  # From Windows (WSL or Git Bash):
  rsync -av --progress \
    "/mnt/c/Users/ppenthoi/.cache/huggingface/hub/models--google--gemma-4-12b-it/" \
    user@your-vm-ip:/opt/models/gemma-4-12b-it/

  This transfers the entire model directory (including the snapshots/ folder) to /opt/models/gemma-4-12b-it/ on the VM.

  ---
  Step 4 — Update the model path in ai_chat.py

  On the VM, edit backend/app/routes/ai_chat.py line 9:

  nano /opt/tcp-analyzer/backend/app/routes/ai_chat.py

  Change:
  # OLD (Windows path)
  MODEL_ID = r"C:\Users\ppenthoi\.cache\huggingface\hub\models--google--gemma-4-12b-it\snapshots\5926caa4ec0cac5cbfadaf4077420520de1d5205"
  To:
  # NEW (Linux path — point to the snapshots subfolder)
  MODEL_ID = "/opt/models/gemma-4-12b-it/snapshots/5926caa4ec0cac5cbfadaf4077420520de1d5205"

  ▎ Important: keep the snapshot hash at the end — that's the exact model version folder. Verify it exists with ls /opt/models/gemma-4-12b-it/snapshots/.

  ---
  Step 5 — Update CORS for your VM's IP

  Edit backend/app/main.py and add your VM's IP/domain to the allowed origins:

  nano /opt/tcp-analyzer/backend/app/main.py

  Change:
  allow_origins=["http://localhost:5173", "http://localhost:3000"],
  To:
  allow_origins=[
      "http://localhost:5173",
      "http://localhost:3000",
      "http://YOUR_VM_IP",          # e.g. http://192.168.1.50
      "http://YOUR_VM_IP:80",
  ],

  ---
  Step 6 — Create Python venv and install dependencies

  cd /opt/tcp-analyzer/backend

  # Create venv with Python 3.11
  python3.11 -m venv .venv

  # Activate it
  source .venv/bin/activate

  # Upgrade pip first
  pip install --upgrade pip

  # Install all dependencies
  # If you have NO GPU (CPU only):
  pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
  pip install -r requirements.txt

  # If you HAVE a CUDA GPU (faster inference):
  pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
  pip install -r requirements.txt

  deactivate

  ▎ torch is ~2GB so this takes a while. The --index-url trick installs the right torch variant for your hardware.

  ---
  Step 7 — Build the frontend (static files)

  cd /opt/tcp-analyzer/frontend

  # Install npm dependencies
  npm install

  # Build production static files → creates frontend/dist/
  npm run build

  This produces /opt/tcp-analyzer/frontend/dist/ — a folder of plain HTML/CSS/JS.

  ---
  Step 8 — Create the systemd service for the backend

  sudo nano /etc/systemd/system/tcp-analyzer-backend.service

  Paste this (replace your_linux_user with your actual username, e.g. ubuntu):

  [Unit]
  Description=TCP Analyzer Backend (FastAPI + Uvicorn)
  After=network.target

  [Service]
  Type=simple
  User=your_linux_user
  WorkingDirectory=/opt/tcp-analyzer/backend
  ExecStart=/opt/tcp-analyzer/backend/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
  Restart=always
  RestartSec=5
  StandardOutput=journal
  StandardError=journal

  # Increase memory limits for the large model (12GB model needs headroom)
  LimitNOFILE=65536

  [Install]
  WantedBy=multi-user.target

  Enable and start it:
  sudo systemctl daemon-reload
  sudo systemctl enable tcp-analyzer-backend
  sudo systemctl start tcp-analyzer-backend

  # Check it's running
  sudo systemctl status tcp-analyzer-backend

  # Watch logs live
  sudo journalctl -u tcp-analyzer-backend -f

  ---
  Step 9 — Configure nginx to serve the frontend + proxy the API

  sudo nano /etc/nginx/sites-available/tcp-analyzer

  Paste:
  server {
      listen 80;
      server_name YOUR_VM_IP;   # replace with your VM's IP or hostname

      # Serve built React frontend
      root /opt/tcp-analyzer/frontend/dist;
      index index.html;

      # All non-API routes → React's index.html (client-side routing)
      location / {
          try_files $uri $uri/ /index.html;
      }

      # Proxy API calls to the FastAPI backend
      location /api/ {
          proxy_pass http://127.0.0.1:8000;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

          # Allow large pcap file uploads (adjust as needed)
          client_max_body_size 500M;

          # Longer timeout for AI inference (Gemma can take 30-60s)
          proxy_read_timeout 300s;
          proxy_connect_timeout 10s;
          proxy_send_timeout 300s;
      }
  }

  Enable the config:
  # Enable the site
  sudo ln -s /etc/nginx/sites-available/tcp-analyzer /etc/nginx/sites-enabled/

  # Remove the default site if present
  sudo rm -f /etc/nginx/sites-enabled/default

  # Test config is valid
  sudo nginx -t

  # Restart nginx
  sudo systemctl restart nginx
  sudo systemctl enable nginx

  ---
  Step 10 — Set correct file permissions

  # Make sure the app user owns the project directory
  sudo chown -R your_linux_user:your_linux_user /opt/tcp-analyzer

  # The data/ directory (SQLite db) is auto-created but make sure it's writable
  mkdir -p /opt/tcp-analyzer/backend/data
  chmod 755 /opt/tcp-analyzer/backend/data

  ---
  Step 11 — Open the firewall port

  # Allow HTTP traffic
  sudo ufw allow 80/tcp
  sudo ufw allow 22/tcp   # SSH (keep this or you'll lock yourself out)
  sudo ufw enable
  sudo ufw status

  ---
  Important notes on the Gemma model

  1. RAM requirement: Gemma 4 12B needs ~24GB RAM (CPU) or ~12GB VRAM (GPU). Make sure your VM has enough memory.
  2. First request is slow: The model loads on the first /api/chat call — this can take 2-5 minutes. Subsequent requests are fast since the model stays in memory.
  3. The snapshot path must be exact: Verify with ls /opt/models/gemma-4-12b-it/snapshots/ and use that exact hash in MODEL_ID.
  4. CPU vs GPU: With no GPU, inference on Gemma 12B is slow (~1-3 min per response). If your VM has an NVIDIA GPU, install the CUDA torch variant in Step 6 and it will be used automatically via
  device_map="auto".

  After any code changes — redeploy steps

  # Backend change → restart service
  sudo systemctl restart tcp-analyzer-backend

  # Frontend change → rebuild and nginx picks it up automatically
  cd /opt/tcp-analyzer/frontend && npm run build
  # nginx serves from dist/ directly, no restart needed

  That's everything. Access the app at http://YOUR_VM_IP once all services are running.
